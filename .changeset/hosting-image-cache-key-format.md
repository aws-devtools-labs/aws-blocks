Fix the CloudFront door caching one image format for every viewer. Image optimization requests (Next.js `/_next/image`, the Nuxt and Astro image endpoints) are keyed by the default behavior's cache policy, which left out `Accept`, so the first viewer's format was served to every later one: a client without WebP support got a cached WebP, or a WebP-capable browser got the source PNG. On image routes the edge router now joins the viewer's `Accept` fields into one value, sends it to the image optimizer as its only `Accept` field, and writes a SHA-256 digest of it into an `x-blocks-image-accept` header that the SSR cache policy keys on when the app has an image optimizer. The optimizer negotiates on exactly the value the cache key covers, so a viewer that rejects a format (`image/webp;q=0`) never gets it from the cache, and a long `Accept` is not forwarded twice. The router keeps `Accept` on image routes even when `cacheKeyHeaders` lists it, and the IPX image function (Nuxt) reads every `Accept` field of an API Gateway event, not only the last. `Accept` stays out of the page cache key. With an image optimizer, `x-blocks-image-accept` is reserved and synth rejects it in `cacheKeyHeaders`; without one, the router leaves that header alone. The header takes a free cache-key header slot; an app whose `cacheKeyHeaders` already uses all five keeps its cache key and gets a `@aws-cdk-blocks/hosting:ImageAcceptNotInCacheKey` synth warning.
