Fix the CloudFront door caching one image format for every viewer. Image optimization requests (Next.js `/_next/image`, the Nuxt and Astro image endpoints) are keyed by the default behavior's cache policy, which left out `Accept`, so the first viewer's format was served to every later one: a client without WebP support got a cached WebP, or a WebP-capable browser got the source PNG. The edge router now copies the viewer's complete `Accept` value into an `x-blocks-image-accept` header on image routes, and the SSR cache policy keys on it when the app has an image optimizer, so a viewer that rejects a format (`image/webp;q=0`) never gets it from the cache. `Accept` stays out of the page cache key. With an image optimizer, `x-blocks-image-accept` is reserved and synth rejects it in `cacheKeyHeaders`; without one, the router leaves that header alone. The header takes a free cache-key header slot; an app whose `cacheKeyHeaders` already uses all five keeps its cache key and gets a `@aws-blocks/hosting:ImageAcceptNotInCacheKey` synth warning.
