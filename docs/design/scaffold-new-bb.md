# Design draft — a scaffolder for new Building Blocks (`create-block`)

> Status: **DRAFT for discussion.** Nothing implemented yet. This captures what a
> Block is, what wiring a new one requires today, and a proposed CLI to automate it.

## 1. What we're building

A command that generates a new Building Block (BB) — the `bb-*` package skeleton
(all conditional-export layers, tests, docs, version script) **and** wires up every
registration touchpoint so the block is buildable, exported from the umbrella
`@aws-blocks/blocks`, and exercised by the comprehensive test app in one step.

Today this is a ~30-minute, error-prone, copy-`bb-kv-store`-and-gut-it ritual with
**6 hand-edited touchpoints** across the monorepo (see §4). It's exactly the kind of
mechanical, easy-to-get-subtly-wrong work a generator should own.

## 2. What constitutes a Block (analyses #1–#2)

From the tech design (`08-building-block-architecture.md`, KIT = AWS Blocks) and the
implemented reality (`AGENTS.md`, `bb-kv-store`):

A BB bundles **three/four implementations behind one strongly-typed import**, selected
by `package.json` conditional exports:

| Export condition | File | Runs when |
|---|---|---|
| `cdk` | `index.cdk.ts` | `cdk synth` (`--conditions=cdk`) — provisions infra, grants IAM |
| `aws-runtime` | `index.aws.ts` | inside the deployed Lambda — real AWS SDK calls |
| `default` + `types` | `index.mock.ts` | `npm run dev` + tests — local mock, persists to `.bb-data/` |
| `browser` | `index.browser.ts` | client bundle — server-side methods stubbed to throw |

Load-bearing conventions every layer shares: extend `Scope` (never wrap it);
`registerSdkIdentifiers()` in the mock/aws ctor and `getSdkIdentifiers()` **at call
time**; `registerConfig()` (never `handler.addEnvironment`) for extra config;
`synthGuard()` stubs for every runtime method in the CDK layer; errors cross the wire
by `name`; `get()`-style reads return `null` for not-found.

### The three Block shapes (this drives the generator)

| Shape | Required files | Example | Notes |
|---|---|---|---|
| **Primitive** (owns new infra) | `index.cdk/aws/mock/browser.ts` + `types.ts` + `errors.ts` + `version.ts` | `bb-kv-store` | full 4-layer split; `fromExisting()` factory |
| **Composite** (composes other BBs, no own infra) | single `index.ts` + `errors.ts` + `version.ts` (+ `index.browser.ts` stub) | `bb-auth-basic` | exports only `browser`/`types`/`default`; no `cdk`/`aws-runtime` conditions |
| **Client-facing** (non-HTTP protocol) | all of Primitive **+** a real `index.browser.ts` / client middleware (Transferable) | `bb-realtime` | atypical layout; **v2**, generate a pointer to `bb-realtime`, not a full template |

## 3. The canonical file skeleton (Primitive, from `bb-kv-store`)

```
packages/bb-{name}/
  package.json          # conditional exports; prebuild version script; files[]
  tsconfig.json         # extends ../../tsconfig.base.json; references core (+ deps)
  api-extractor.json    # mainEntryPointFilePath → dist/index.aws.d.ts
  README.md             # H1 + first-sentence blurb (feeds the catalog), "When to use / not"
  DESIGN.md             # internals + mock↔AWS differences
  LICENSE
  src/
    version.ts          # GENERATED by prebuild — BB_NAME, BB_VERSION (never hand-edit)
    types.ts            # TYPES ONLY (import type only)
    errors.ts           # {Class}Errors as-const, wire-name strings ("...Exception")
    index.mock.ts       # default + types entry; persists to getMockDataDir()
    index.aws.ts        # aws-runtime; SDK client w/ buildUserAgentChain()
    index.cdk.ts        # cdk; provisions infra, grants on this.handler, synthGuard stubs
    index.browser.ts    # stub class (no-op ctor) + re-export errors
    index.test.ts       # node:test; resets .bb-data in beforeEach
    parity.test.ts      # mock↔aws↔browser behavioral parity
    index.cdk.test.ts   # Template.fromStack assertions; synthGuard throws
```

Composite collapses this to a single `index.ts` (+ `errors.ts`, `version.ts`, browser
stub) and a 3-condition export map (`browser`/`types`/`default`).

## 4. What wiring a new BB requires today (analysis #3)

`packages/*` is **not** a workspace glob — the root list is explicit. Six touchpoints
are hand-edited and **none** are generated from the block's source:

1. **`packages/blocks/src/index.ts`** — JSDoc block + `export { Class, ClassErrors }` +
   `export type {...}` (alias colliding type names, e.g. `PutOptions as KVPutOptions`).
2. **`packages/blocks/src/index.cdk.ts`** — terse value + type re-export (no JSDoc).
3. **`packages/blocks/package.json`** — add to `dependencies` (caret) **and** the
   `aws-blocks.vendorize` map (`pkg → [ClassName]`).
4. **root `package.json` `workspaces`** — append `"packages/bb-{name}"`.
5. **`test-apps/comprehensive`** — dep as `"*"` + a `new {Class}(scope, ...)` instance in
   `aws-blocks/index.ts` + a `test/{name}.test.ts` (zero casts).
6. **`npx changeset add`.**

**Derived artifacts are already automated — the generator should *call* these, not
duplicate them:** `npm run sync-docs` (README catalog table between markers);
`packages/blocks` prebuild/prepack runs `gen-block-docs.mjs`; `packages/core` prebuild
runs `generate-bb-names.mjs` off the vendorize map. So updating touchpoint #3's
vendorize map is enough for the telemetry allowlist to regenerate.

## 5. Relation to "extending with existing resources" (analysis #4)

The extending guide's **Pattern 3 (Custom BB)** is the *external* mirror of this: a user
in their own repo authors the same 3-file shape under their `packages/bb-*`, names it
`@their-org/bb-*`, pins the same `aws-cdk-lib`/`constructs` peers, tags `keywords:
["aws-blocks"]`, and skips **all** monorepo wiring (§4 touchpoints 1–5 don't exist for
them). Same skeleton, different (or absent) wiring. The guide literally recommends
"copy `bb-kv-store`, rename, gut it" — i.e. begging for a generator.

This gives us **two audiences** with the same core template but opposite wiring needs —
the key decision in §7.

## 6. Proposed CLI

Mirror `create-blocks-app` exactly (it's the house style): **zero runtime deps**, pure
`node:` stdlib, ESM, plain `tsc` build, manual `process.argv` parsing, `node:readline`
prompts, `--yes` to skip. Templates are real directories copied with `cp` + structural
edits (not string templating).

- **Invocation:** `npm create @aws-blocks/block@latest MyBlock` (a new
  `packages/create-block` package, bin `create-block`), plus a repo convenience alias
  `npm run new:bb` for contributors.
- **Auto-detect mode** (same trick as `create-blocks-app` detecting Amplify), in priority
  order:
  - **contributor** — inside the `aws-blocks` monorepo → generate package + do all 6
    touchpoints.
  - **customer** — inside *your own* npm-workspaces repo → generate `packages/bb-*`,
    register it in your root `workspaces` (unless a `packages/*` glob already covers it),
    and `npm install` so your app can import it without publishing. App code untouched;
    scope derived from your root package name (or `--scope`). This is the "scaffold **and
    link** a subpackage" case.
  - **external** — anywhere else → standalone `@<scope>/bb-*`, `keywords: ["aws-blocks"]`,
    no workspace wiring.
- **Prompts / flags:** block class name (PascalCase, no "BB" prefix) → package name
  `bb-{kebab}`; `--type primitive|composite` (`--client-facing` = v2 pointer);
  `--dir`, `--yes`, `--skip-install`, `--dry-run`.
- **Generates:** the §3 skeleton for the chosen type, with the class name, package name,
  and `generate-version.mjs {Class}` arg substituted; a starter method (`get`/`put` for
  primitive) so it builds and tests green out of the box; a `changeset`.
- **Wires (contributor mode):** all 6 touchpoints programmatically (JSON edits for
  package.jsons/workspaces; marker- or anchor-based insertion for the two umbrella
  `index*.ts` re-export lists, kept alphabetical), then runs `npm run sync-docs` and
  prints the remaining human step (add a real instance + assertions to comprehensive —
  we scaffold a stub, the author fleshes it out).
- **Verifies:** ends by running `npm run build -w @aws-blocks/bb-{name} && npm test -w …`
  (skippable) so the author starts from green.

2. **Block types in v1** — Primitive + Composite (cover the common cases), or add

3. **Packaging** — published `npm create @aws-blocks/block` bin, a repo-only

4. **Umbrella re-export editing** — insert via HTML markers we add to `index.ts` /
   `index.cdk.ts` (robust) vs. anchored alphabetical insertion into the existing
