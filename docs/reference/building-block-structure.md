# Building Block Structure

The files inside a Building Block (BB) package and what goes in each. [Building Block Layer Architecture](./ARCHITECTURE-LAYERS.md) explains why the layers exist; this page is the file-by-file view. Everything here is drawn from [`packages/bb-kv-store`](../../packages/bb-kv-store/), the canonical reference. Read it to learn the shape, but don't copy its DynamoDB data model.

> **Scaffolding a new BB?** `npm run new:bb` generates this skeleton and wires up the monorepo (see [`docs/design/scaffold-new-bb.md`](../design/scaffold-new-bb.md)). The checklist for finishing one is in [`AGENTS.md`](../../AGENTS.md#-authoring-a-new-building-block).

## File layout

```
packages/bb-{name}/
  package.json          # conditional exports, prebuild version script, files[]
  tsconfig.json         # extends ../../tsconfig.base.json; references core and every BB it imports
  api-extractor.json    # mainEntryPointFilePath → dist/index.aws.d.ts
  README.md             # user doc: first sentence feeds the umbrella catalog; runnable snippets
  DESIGN.md             # internals and mock ↔ AWS differences
  API.md                # GENERATED by `npm run update:api` — never hand-edit
  LICENSE
  src/
    version.ts          # GENERATED by prebuild — BB_NAME, BB_VERSION
    types.ts            # types only (`import type` only; no values)
    errors.ts           # {Class}Errors as-const map of wire names
    index.mock.ts       # `default` + `types` entry: local implementation
    index.aws.ts        # `aws-runtime` entry: AWS SDK implementation
    index.cdk.ts        # `cdk` entry: provisions infrastructure
    index.browser.ts    # `browser` entry: stub class + error constants
    index.test.ts       # node:test against the mock
    parity.test.ts      # mock ↔ AWS behavioural parity
    index.cdk.test.ts   # synth assertions (Template.fromStack), synthGuard stubs throw
```

## `package.json`

```jsonc
{
  "name": "@aws-blocks/bb-kv-store",
  "type": "module",
  "files": ["dist", "README.md", "DESIGN.md", "src", "LICENSE"],
  "exports": {
    ".": {
      "browser": "./dist/index.browser.js",
      "cdk": { "types": "./dist/index.cdk.d.ts", "default": "./dist/index.cdk.js" },
      "aws-runtime": "./dist/index.aws.js",
      "types": "./dist/index.mock.d.ts",
      "default": "./dist/index.mock.js"
    }
  },
  "scripts": {
    "prebuild": "node ../../scripts/generate-version.mjs KVStore",
    "build": "tsc --build",
    "test": "node --test --test-concurrency=1 dist/*.test.js"
  }
}
```

Regenerate `files[]` and the `test` glob from your own `src/`; don't copy another block's. AWS SDK clients are `dependencies`; `aws-cdk-lib` and `constructs` are `peerDependencies`.

## The mock layer (`index.mock.ts`)

Extends `Scope` from `@aws-blocks/core`, registers a `mock-`-prefixed resource name, and persists under `getMockDataDir(this)` (`.bb-data/{fullId}/`):

```typescript
export class KVStore<T = string> extends Scope {
	constructor(scope: ScopeParent, id: string, options?: KVStoreOptions<T>) {
		super(id, { parent: scope, bbName: BB_NAME, bbVersion: BB_VERSION });
		this.filePath = join(getMockDataDir(this), 'store.json');
		registerSdkIdentifiers(this.fullId, { tableName: `mock-${this.fullId}`.substring(0, 255) });
		// …
	}
}
```

It implements the whole public API with the same semantics as AWS (`get()` returns `null` when absent, conditional writes throw `{Class}Errors.*`). Where it cannot match AWS, `DESIGN.md` says so.

## The AWS runtime layer (`index.aws.ts`)

Extends `Scope` from `@aws-blocks/core`, registers the **derived** resource name in its constructor, builds its SDK client with the BB's user-agent chain, and resolves names at call time:

```typescript
export class KVStore<T = string> extends Scope {
	readonly bbName = BB_NAME;

	constructor(scope: ScopeParent, id: string, options?: KVStoreOptions<T>) {
		super(id, { parent: scope, bbName: BB_NAME, bbVersion: BB_VERSION });
		const tableName = options?.table ? options.table.tableName : this.fullId.substring(0, 255);
		registerSdkIdentifiers(this.fullId, { tableName });
		const client = new DynamoDBClient({ customUserAgent: this.buildUserAgentChain() });
		installClientUserAgent(client);
		this.docClient = DynamoDBDocumentClient.from(client);
	}

	async get(key: string): Promise<T | null> {
		const result = await this.docClient.send(new GetCommand({
			TableName: getSdkIdentifiers(this).tableName,   // ← call time, never cached in the constructor
			Key: { pk: key },
		}));
		if (!result.Item) return null;
		// …
	}
}
```

## The CDK layer (`index.cdk.ts`)

Extends `BuildingBlockScope` from `@aws-blocks/core/cdk`, which also takes the block's VPC requirements (`vpc: {}` when there are none). It provisions the resource under the same derived name, follows the stack defaults for removal policy and deletion protection, grants on the **shared execution role**, and stubs every runtime method. It does not register SDK identifiers:

```typescript
export class KVStore extends BuildingBlockScope {
	static fromExisting(tableName: string): ExternalTableRef {
		return { __brand: 'ExternalTableRef' as const, tableName };
	}

	constructor(scope: ScopeParent, id: string, options?: KVStoreOptions<unknown>) {
		super(id, { parent: scope, vpc: { gatewayEndpoints: [ec2.GatewayVpcEndpointAwsService.DYNAMODB] } });
		this.table = new Table(this, 'table', {
			tableName: this.fullId.substring(0, 255),
			removalPolicy: /* options.removalPolicy, else */ this.defaults.removalPolicy,
			deletionProtection: options?.deletionProtection ?? this.defaults.deletionProtection,
			// …
		});
		this.table.grantReadWriteData(this.executionRole);
	}

	get(..._args: unknown[]): never { return synthGuard('KVStore', 'get'); }
	put(..._args: unknown[]): never { return synthGuard('KVStore', 'put'); }
	// … one stub per runtime method
}
```

Pass extra (non-name) config to the runtime with `registerConfig(this, 'BLOCKS_…', value)`, never `handler.addEnvironment()`.

## The browser layer (`index.browser.ts`)

Client bundles import the BB's package too (for types and error constants), so the browser entry must load without server dependencies:

```typescript
export class KVStore {
	constructor(...args: any[]) {}
}
export { KVStoreErrors } from './errors.js';
```

## `types.ts`, `errors.ts`, `version.ts`

- **`types.ts`** holds the shared option and result types, imported by every layer. Types only: `import type`, no `const`, function or class.
- **`errors.ts`** exports `{Class}Errors`, an as-const map from a constant to its wire name (`ConditionalCheckFailed: 'ConditionalCheckFailedException'`). Errors cross the wire by `name`; callers match with `isBlocksError(e, KVStoreErrors.ConditionalCheckFailed)`.
- **`version.ts`** is generated by the `prebuild` script (`BB_NAME`, `BB_VERSION`, used for user-agent attribution). Never edit it.

## Tests

Tests use `node:test` and `node:assert` and run on the compiled `dist/`. Reset `.bb-data` between tests. `parity.test.ts` drives the mock and the AWS layer (against a spied SDK client) through the same calls and expects the same observable results. Mock tests cannot catch AWS serialization bugs, so behaviour changes on the AWS path also need a sandbox e2e in `test-apps/comprehensive`.

## Blocks that don't fit this shape

- **Composite BBs** build on other BBs by constructing them, with themselves as the parent, in every layer. `Auth` (`packages/bb-auth`) composes a `KVStore` and an `AppSetting` this way and keeps the four-layer split because it can also own a Cognito user pool. See [Composition](./ARCHITECTURE-LAYERS.md#composition).
- **Client-facing BBs** return live objects to the browser (Transferables) and ship client middleware. `bb-realtime` uses a single `index.ts` as its `default` entry, plus `index.aws.ts`, `index.cdk.ts` and middleware files. Don't copy its layout for an ordinary BB.
