# Building Block Structure

## Standard Package Shape

A typical Building Block is a package with conditional entry points. The
following shape is used by data-oriented first-party Blocks such as
`@aws-blocks/bb-kv-store`:

```
packages/bb-example/
├── README.md
├── DESIGN.md
├── API.md                 # generated by API Extractor
├── api-extractor.json
├── package.json
├── tsconfig.json
└── src/
    ├── index.cdk.ts
    ├── index.aws.ts
    ├── index.mock.ts
    ├── index.browser.ts
    ├── index.test.ts
    ├── index.cdk.test.ts
    ├── parity.test.ts
    ├── types.ts
    ├── errors.ts
    └── version.ts         # generated during prebuild
```

Do not treat this as a required file list. A Block that has no browser API or
owns no AWS infrastructure can use fewer entry points. Choose the closest
first-party Block with the same responsibility and keep only the exports its
public API needs.

## Export Map

The package export map selects the implementation. This is the shape used by
the standard multi-layer Blocks:

```json
{
  "type": "module",
  "exports": {
    ".": {
      "browser": "./dist/index.browser.js",
      "cdk": {
        "types": "./dist/index.cdk.d.ts",
        "default": "./dist/index.cdk.js"
      },
      "aws-runtime": "./dist/index.aws.js",
      "types": "./dist/index.mock.d.ts",
      "default": "./dist/index.mock.js"
    }
  }
}
```

The CDK application must run with `--conditions=cdk`; the bundled Lambda runs
with `--conditions=aws-runtime`. Local development and tests use the default
mock entry point. The browser condition must never import AWS SDK or CDK code.

## Implementation Rules

- Extend `Scope`; do not wrap it. `Scope` provides hierarchy, resource
  discovery, IAM propagation, and the stable `fullId` used by every layer.
- Keep types in `types.ts` type-only so they can be imported safely across
  environments.
- The CDK entry point creates resources, grants access to `this.handler`, and
  uses `registerConfig()` for non-derived runtime configuration.
- Runtime and mock entry points expose compatible APIs. Add parity tests when
  both have behavior that must agree.
- Use `synthGuard()` for runtime-only methods on CDK constructs, rather than
  allowing data access during synthesis.
- Keep browser stubs browser-safe. Methods that are server-only should fail
  explicitly rather than pulling server dependencies into the client bundle.
